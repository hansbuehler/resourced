## Host Resource Guardrails

- When using any common directory, such as `/tmp` or a shared storage root,
  first create a clearly named project-specific subdirectory and place every
  file generated by that project beneath it. Do not scatter project outputs,
  logs, checkpoints, caches, or intermediate files directly across a common
  directory; keep them together so ownership and cleanup remain unambiguous.
- Every project-owned process that can run longer than a few minutes must
  emit lightweight, flushed progress information at regular intervals. At a
  minimum report elapsed time, completed and total work units, and an
  estimated remaining time when meaningful; write it to the persistent job
  log without retaining large intermediate arrays or adding material
  synchronization cost. This must make it possible to distinguish active
  computation from a stalled process without attaching a profiler or
  restarting the job, and it is also what a STOP action below falls back on
  if a clean shutdown does not finish in time.
- Detached jobs and user services do not inherit the interactive shell setup.
  Launch them with the explicit project interpreter and working directory,
  and set required project environment variables explicitly in the job
  definition (for example a data-root variable and `PYTHONPATH`) rather than
  relying on values set in an interactive shell. Before starting material
  work, validate imports and data-root discovery in the same detached
  environment that will run the job.
- Check resource headroom with `gpuctl resources --json` before launching
  material work and during every regular background-process inspection.
  Thresholds for RAM and each monitored disk path are configured once in
  `resourced`'s `config.toml`; do not duplicate or second-guess them here,
  and do not measure RAM or disk usage by other means. The output has one
  entry per configured check under `checks`, each with a `health` of `OK`,
  `WARN`, `STOP`, or `UNAVAILABLE`/`ERROR` (treat the latter two as `STOP`,
  since the limit could not be verified); take the worst `health` across all
  checks. Example:
    {"checks": [{"name": "ram", "health": "OK", "current": {"free_gib": 958.6, ...}}]}
  Resource-triggered action applies only to jobs owned by the current
  project; never terminate unrelated system or user activity.
    - `OK` (all checks): proceed normally.
    - `WARN` on any check: warn the user promptly, including the check's
      `name` and `error` if present; identify the largest owned processes
      and whether usage is stable or increasing. For a disk check, start a
      safe cleanup limited to stale or reproducible files owned by the
      current project; never blanket-delete a shared directory, remove open
      or shared files, or delete reusable caches owned by others.
    - `STOP`, `UNAVAILABLE`, or `ERROR` on any check: do not launch more
      work. For each active job owned by the current project, request a
      graceful stop (its own checkpoint-and-exit signal, or SIGTERM if it
      has none) and wait up to 60 seconds for it to save and exit on its
      own. If it has not exited by then, send SIGKILL — do not wait longer,
      since that only worsens the resource condition. Rely on the job's last
      periodic checkpoint (see the progress-logging rule above) as the
      recovery point; if the job's own log shows the final checkpoint save
      failed or did not finish, do not retry it under pressure — note in the
      alert that only the prior periodic checkpoint is trustworthy.
      Immediately raise an alert in the active user conversation stating
      which jobs were stopped, whether each exited cleanly or was killed,
      and whether its final checkpoint is trustworthy; then ask before
      releasing any GPU allocation those jobs held (`gpuctl release`). If
      the owning process is already gone, release it directly (`gpuctl
      release --force`) since nothing is at risk. Do not restart until
      `gpuctl resources` shows `OK` on every check again and the cause has
      been assessed.
    - If `gpuctl resources`/`status`/`verify` fail only because the sandbox
      cannot reach the resourced socket (`no permission to use ... socket`
      while the daemon itself is running), that is an environment
      configuration gap, not a resource emergency: do not terminate jobs on
      this basis alone, and ignore the `UNAVAILABLE` results of the local
      fallback measurement it triggers. Report it once and ask the user to
      allow socket access in the sandbox (for Codex CLI:
      `[sandbox_workspace_write] network_access = true`). Do not escalate to
      bypass the sandbox without asking first.
- Launch every GPU process as `gpuctl run --gpus N -- python ...`, never by
  setting `CUDA_VISIBLE_DEVICES` yourself or after `eval "$(gpuctl env ...)"`.
  In a sandboxed agent (Codex CLI) GPUs are only visible to commands that run
  outside the sandbox, and the host's agent rules allow exactly that form to
  do so; other forms (including `gpuctl run --allocation REF`) need the user's
  approval to leave the sandbox. A GPU program that finds no device must not
  silently fall back to CPU while holding a claim.
- Run everything that does not need a GPU (tests, data preparation, analysis)
  with `JAX_PLATFORMS=cpu`, and `CUDA_VISIBLE_DEVICES=` (empty) for other CUDA
  frameworks such as PyTorch. A JAX program started outside `gpuctl` otherwise
  opens a context on every GPU, including GPUs claimed by other jobs, and
  `gpuctl verify` reports it as `FOREIGN PROCESS`. If a project's test setup
  does not enforce this, set it on the command line, e.g.
  `JAX_PLATFORMS=cpu python -m pytest ...`.
- Treat Git working trees (for example under `~/python`) as source
  repositories rather than general-purpose data or artifact storage.
  Regularly inspect repository status, total footprint, untracked files, and
  unusually large files. Keep only relevant source, configuration,
  specifications, tests, and deliberately retained project artifacts in Git
  roots. Never remove user files merely because they are large without
  first identifying ownership and obtaining any required approval.
